## [1.1.0] — 2026-08-07

**The XP fix.** Target: Build 42.20.2.

If you played 1.0.0 on any recent Build 42, chopping trees gave you nothing at all. This release is
that bug and everything it was hiding.

### Fixed

- **Chopping trees awarded no Woodcutting XP.** Build 42 moved tree felling off the combat path:
  `ISChopTreeAction:animEvent` calls `IsoTree.WeaponHit` directly, and that method raises no Lua
  event. `OnWeaponHitTree` is triggered only from `CombatManager.processMaintenanceCheck`, behind
  `isActuallyAttackingWithMeleeWeapon()`, so it never fired for the chop action. Every reward in
  the mod hung off it. The mod now wraps the timed action instead. *Reported independently by three
  players.*
- **Tree-felled bonus XP, all extra loot, and the tree counter never triggered** — the same root
  cause, via a `Woodcutting.onTreeFelled` dispatch that could not fire. With the skill pinned at
  level 0, the damage scaling, one-hit threshold and loot skill-bonus were dead too.
- **A felled tree could be credited to the wrong tree.** Detection scanned the 3×3 around the
  character and took the first neighbour it found. It now uses the action's own `self.tree`.
- **The Sandbox page and the Woodcutter trait showed raw keys** such as
  `Sandbox_Woodcutting_xpMultiplier`, in every language. Build 42.15 replaced the `.txt`
  translation tables with `.json` and 42.20.2 reads nothing else; no `Sandbox.json` or `UI.json`
  existed.
- **Translations never loaded on Linux dedicated servers.** The folders were `translate/en`, which
  Windows resolves case-insensitively and Linux does not.
- **The Nature Abundance sandbox setting had no effect on loot rates.** The adjustment mutated its
  own table and ran before the sandbox bridge overwrote it. It is now pure and driven from the
  bridge.
- **Wall vines granted bush XP and counted as bush kills.** Vanilla reuses `ISRemoveBush` for both
  jobs; stripping ivy off a wall is not woodcutting.
- **The documented way to disable one-hit felling was impossible.** The README and every tooltip
  said "set above 10", while the option itself capped at 10.
- Literal `%` in translation strings, which Build 42.20.1 requires written as `%%`.

### Added

- **Woodcutting XP for clearing bushes** (`bushRemovedXp`, new Sandbox option), and the
  `bushkills` counter that the Kill Count integration had always displayed but nothing ever wrote.
- **Calorie saving per level** while chopping. `caloriesSavedModifierPerLevel` had been configured
  since 1.0.0 and never read by anything.
- **Spanish, French and Portuguese** joined English and Brazilian Portuguese as fully translated —
  skill name and description, all 19 Sandbox options with tooltips, and the Woodcutter trait.
- `author` and `modversion` in `mod.info`.

### Changed

- Damage scaling is now also applied immediately before `IsoTree.WeaponHit` reads
  `getTreeDamage()`, so it no longer depends on `OnEquipPrimary` firing server-side for a remote
  player.
- `oneHitLevelThreshold` accepts up to **99**. The runtime test is a plain `level >= threshold` and
  levels stop at 10, so the range itself is the switch: `0` makes every tree fall in one swing from
  the start, `11`–`99` disables one-hit felling. Both edges are now spelled out in the tooltips.
- Translations moved to `common/media/lua/shared/Translate/<LANG>/`, shared across all 42.x
  versions, and are generated by `scripts/gen_translations.py` rather than hand-maintained.

### Removed

- The legacy `*_EN.txt` / `*_PTBR.txt` / `*_ES.txt` / `*_FR.txt` translation tables, which Build
  42.20.2 does not read.
- The `OnTick` polling used for felled-tree detection.
- An empty client-side trait stub that collided by filename with the real shared one, and a stale
  `steamdesc.txt` that shipped inside the uploaded folder.

### Internal

- Rewards are dispatched through three registries — `Woodcutting.addOnTreeHit`,
  `addOnTreeFelled`, `addOnBushRemoved` — so engine-facing detection (shared) stays separate from
  server-authoritative rewards (server-only). Callbacks run under `pcall`.
- `AGENTS.md` documents the Build 42 engine behaviour verified by decompiling `projectzomboid.jar`,
  including the several plausible-looking "fixes" that are wrong and why.
- `tests/harness.lua` runs the real mod Lua against the real vanilla timed-action classes:
  29 assertions covering per-swing XP, the felled latch, the multiplayer-client guard, wall vines,
  the threshold edges, TreeDamage snapshot stability and abundance scaling.

### Verification

Static: Lua parses as 5.1, every Java API checked against the 42.20.2 jar, 15 translation JSONs
parse as UTF-8, all 19 Sandbox options present in all 5 languages, no lone `%` in any parsed file.

Runtime: the behavioural harness passes 29/29; a dedicated server boots with the mod, registers the
perk, applies both timed-action patches and generates the full Sandbox block; and the in-game
checks in `AGENTS.md` §11 were run against Build 42.20.2.

### Upgrading

Safe to drop into an existing save — no mod-data migration, and absent counters initialise on
first use. Anyone who was stuck at Woodcutting 0 will simply start earning XP.

## [1.0.0] — 2026-06-16

Initial Build 42 release: an overhaul of *Woodcutting Skill* by Champy, with per-level tree damage
and an optional one-hit threshold, endurance savings, reworked extra loot on medium and large
trees, the Woodcutter trait, profession and trait XP boosts, and a dedicated Sandbox page.

Shipped with the XP system wired to `Events.OnWeaponHitTree`, which Build 42 no longer raises for
tree chopping. See 1.1.0.
